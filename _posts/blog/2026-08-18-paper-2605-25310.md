本記事は [Tool-Call Dependency Structure is Linearly Decodable in LLM Agent Residual Streams](https://arxiv.org/abs/2605.25310)（arXiv:2605.25310）の解説記事です。

## 論文概要

ツールを使用するLLMエージェントが生成する軌跡（trajectory）には、先行するツール出力が後続のツール呼び出し引数に供給されるという依存構造が存在する。この依存構造は有向非巡回グラフ（DAG）として表現できるが、モデル内部でこの構造がどう表現されているかは未知であった。著者らはQwen3-32Bの残差ストリームに対し低容量の線形エッジプローブを適用し、ツール呼び出し依存グラフがランダムラベル制御および位置ベースラインの双方を有意に上回る精度でデコード可能であることを実証している。反事実的対照実験と層ごとのactivation patchingにより、この信号が抽象的なトポロジーを追跡し伝播する表現であることを示した。

この記事は [Zenn記事: AIエージェントのツール設計原則：選択精度を高める7つの実践パターン](https://zenn.dev/0h_n0/articles/b2b62296cac899) の深掘りです。Zenn記事の「ツール設計がエージェント品質を決める理由」に対し、LLMがツール間の依存関係をどう内部的に表現しているかの基礎的知見を提供する論文です。

## 背景と動機

LLMエージェントのツール呼び出しに関する研究は、選択精度やプランニング手法に焦点が当てられてきた。しかし、実行時に生成されるツール呼び出し列の依存構造（「ツールAの出力がツールBの引数に供給される」DAG）がモデル内部でどう表現されているかは未探索であった。

Mechanistic interpretabilityでは静的コードや思考連鎖に対する構造的プローブの適用例があるが、エージェントのランタイムツール呼び出し依存グラフを対象としたプローブは存在しなかった。著者らは「残差ストリームからツール呼び出し依存構造を線形にデコードできるか」という問いを立てている。依存構造がモデル内部で表現されているならば、その表現の質がツール呼び出しの正確さを左右する可能性がある。

## 主要な貢献

著者らが報告している本論文の主要な貢献は以下の通りである。

1. **ランタイムツール呼び出し依存グラフの初の構造的プローブ**: Qwen3-32Bの残差ストリームに対する線形エッジプローブで、依存グラフをAUROC 0.869（直接辺）、0.986（推移的辺）でデコード
2. **Hewitt-Liangランダムラベル制御の適用**: 500回の順列テストで$p < 10^{-4}$を達成し、プローブが真の構造を捉えていることを検証
3. **反事実的対照実験**: 値の破壊（Cohen's $d = 0.06$）と構造的摂動（Cohen's $d = 0.87$）の対比により、信号が識別子の値ではなく抽象的トポロジーを追跡することを実証
4. **層ごとのactivation patching**: Layer 57で最大のパッチ効果（$\Delta_{\text{patch}} = +0.01605$）を示し、表現が伝播することを確認
5. **クロスベンチマーク再現**: ToolHop、ComplexFuncBench、$\tau^2$-bench Telecomで再現、シングルショットプランニング（TaskBench）では信号が消失

## 技術的詳細

### エッジプローブの設計

著者らが使用したプローブは、L2正則化付きロジスティック回帰である。低容量プローブを選択した理由は、線形デコーダビリティの検証にあたり、プローブ自体が構造を学習してしまう（Hewitt & Liang, 2019が指摘した問題）リスクを最小化するためである。

入力特徴量は、ツール呼び出し境界における残差ストリームベクトルの平均プーリングを行い、呼び出しペア$(i, j)$に対して2つのベクトルを連結する。

$$
\mathbf{x}_{ij} = [\bar{\mathbf{H}}_i; \bar{\mathbf{H}}_j]
$$

ここで、
- $\bar{\mathbf{H}}_i$: 呼び出し$i$の境界トークンにおける残差ストリームベクトルの層集合$\{0, 14, 28, 41, 50, 57, 64\}$にわたる平均プール（次元5,120）
- $[\cdot;\cdot]$: ベクトル連結（最終次元10,240）

ラベル$y_{ij}$は、呼び出し$i$の出力に含まれる4文字以上の部分文字列が呼び出し$j$のJSON引数に出現する場合に$y_{ij}=1$（直接辺）とする部分文字列マッチングオラクルで生成される。

プローブのハイパーパラメータは以下の通りである。
- 正則化強度: $C = 0.01$（逆正則化）
- クラス重み: balanced（正例286、負例843の不均衡に対応）
- ソルバ: L-BFGS、最大反復2,000回
- 前処理: StandardScaler（学習フォールドのみでfit）

### ランダムラベル制御と位置ベースライン

**Hewitt-Liangランダムラベル制御**: 辺ラベルを一様シャッフルしパイプライン全体を500回再実行。観測AUROC 0.869に対し順列の最大値は0.565であり、$p < 10^{-4}$で帰無仮説を棄却。

**位置ベースライン**: 位置特徴量$\mathbf{B} = [i, j, j-i, n_{\text{agent}}, j/n_{\text{agent}}]$のみのロジスティック回帰。AUROCは0.792であり、条件付きプロービングにおける残差ストリームの追加寄与は$+0.0775$（95% CI: $[+0.032, +0.127]$）と報告されている。

### 反事実的対照実験

著者らは信号が「値」と「構造」のどちらを追跡しているかを2つの介入で比較している。

**値の破壊**: ツール出力の`_id`フィールドを別の有効なIDに差し替え。Cohen's $d = 0.06$（Wilcoxon $p = 0.11$）で効果なし。**構造的摂動**: 同じ位置のツール応答を`"{}"`に書き換え。Cohen's $d = 0.87$（$p = 1.18 \times 10^{-11}$）で有意。ComplexFuncBenchでも再現（値破壊: $d = +0.018$、構造的摂動: $d = +0.702$）。内部表現は文字列値ではなく抽象的トポロジーを追跡していると著者らは結論している。

### Activation Patching

80のミニマルペア（1本のオラクル辺のみが異なる軌跡A, B）を使用し、軌跡Bの層$L$の残差ストリームを軌跡Aで置換してプローブ出力のシフトを測定する。

$$
\Delta_{\text{patch}}(L) = f(\mathbf{H}^{B \leftarrow A}_L) - f(\mathbf{H}^{B}_L)
$$

ここで$f(\cdot)$は学習済みプローブ出力、$\mathbf{H}^{B \leftarrow A}_L$は軌跡Bの層$L$に軌跡Aの活性化を注入した残差ストリームである。$\Delta_{\text{patch}} > 0$はドナー方向へのシフトを意味する。

Qwen3-32Bでは層57で最大効果（$\Delta_{\text{patch}} = +0.01605$、97.5%がドナー方向）を示し、後続の非パッチ境界でも$\Delta_{\text{decode}}^{\text{fwd}} = +0.0082$（87.5%がドナー方向）のシフトが観測されている。著者らはこれを表現が能動的に伝播する証拠と解釈している。ただし実際のツール呼び出しは0%シフトであり、表現の変化が行動に直結するわけではない。

## 実装のポイント

### プロービング手法の実装

本論文のプローブはscikit-learnの`LogisticRegression`で実装されており、大規模なフレームワークを必要としない。再現に際しての注意点は以下の通りである。

```python
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import LeaveOneGroupOut
import numpy as np


def build_edge_probe(
    features: np.ndarray,
    labels: np.ndarray,
    groups: np.ndarray,
) -> list[float]:
    """Leave-One-Group-Out CVでエッジプローブを評価

    Args:
        features: 連結残差ストリームベクトル (N_pairs, 10240)
        labels: 辺ラベル (N_pairs,) 0 or 1
        groups: 軌跡ID (N_pairs,)

    Returns:
        各フォールドのAUROCスコアのリスト
    """
    logo = LeaveOneGroupOut()
    scores: list[float] = []

    for train_idx, test_idx in logo.split(features, labels, groups):
        scaler = StandardScaler()
        X_train = scaler.fit_transform(features[train_idx])
        X_test = scaler.transform(features[test_idx])

        probe = LogisticRegression(
            C=0.01,
            class_weight="balanced",
            solver="lbfgs",
            max_iter=2000,
            random_state=42,
        )
        probe.fit(X_train, labels[train_idx])
        proba = probe.predict_proba(X_test)[:, 1]
        # AUROC計算は省略
        scores.append(_compute_auroc(labels[test_idx], proba))

    return scores
```

**交差検証**: per-trajectory leave-one-group-out CV（105フォールド）を採用。per-boundary CVは文脈漏洩のため除外されている。bf16精度でNVIDIA GH200 120GB GPU上で推論を実行。

**非線形プローブとの比較**: MLPプローブ（10,240→1024→256→1）のAUROCは0.866であり線形プローブの0.869を上回らない。依存構造は線形にデコード可能である。

## 実験結果

### 主要ベンチマークでの性能

著者らはτ-bench Retail（105軌跡、1,129ペア）を主要データセットとして使用し、3つの追加ベンチマークでクロスドメイン再現を検証している（論文Table 2より）。

| ベンチマーク | 直接辺AUROC | 推移的辺AUROC | 位置のみ | $\Delta_{\text{resid-pos}}$ |
|-------------|-----------|-------------|---------|---------------------------|
| $\tau$-bench Retail | 0.889 | 0.977 | 0.790 | +0.155 |
| ToolHop | 0.854 | 0.966 | 0.805 | +0.161 |
| ComplexFuncBench | 0.849 | 0.943 | 0.872 | +0.060 |
| $\tau^2$-bench Telecom | 0.935 | --- | 0.660 | +0.269 |
| TaskBench（シングルショット） | 0.894 | 0.888 | 0.891 | -0.02 |

**TaskBenchの特異性**: TaskBenchではすべてのツール呼び出しが実行フィードバックなしに一括発行される（シングルショットプランニング）。この場合、呼び出し順序だけで依存関係を十分に予測でき（位置ベースラインAUROC 0.891）、残差ストリームからの追加的な構造情報は消失する（$\Delta_{\text{resid-pos}} = -0.02$）。著者らはこれを「対話的フィードバックが依存構造の内部表現を駆動する」証拠として解釈している。

### マルチシード頑健性とホップ数層別化

3シード（42, 43, 44）での推移的辺AUROCは$0.977 \pm 0.012$であり安定している。ホップ数の増加に伴いAUROCも上昇する: 1ホップ0.869、2ホップ0.974、3ホップ以上0.995。長い軌跡ほど依存構造の表現が強化される傾向がある（2-3呼び出し: 0.942、7+呼び出し: 0.998）。

## 実運用への応用

Zenn記事「AIエージェントのツール設計原則」で述べられている7つのパターンに対し、本論文は以下の示唆を与える。

**1. 逐次実行の合理性**: シングルショットでは依存構造の内部表現が消失するため（TaskBenchの結果）、マルチホップタスクではReACtのような逐次的ツール実行が構造的表現の観点からも合理的である。

**2. 構造的接続パターンの重要性**: 反事実的対照実験から、モデルはID値の文字列ではなく抽象的トポロジーを追跡している。ツール間の構造的接続パターンの設計が、出力形式の詳細よりも重要であることを示唆する。

**3. ランタイム検証への応用**: プローブ手法をプロダクション環境に統合すれば、依存構造の認識状態をモニタリングでき、プローブAUROCの低下を早期警告指標として利用できる。

## まとめと今後の展望

本論文は、LLMエージェントのランタイムツール呼び出し依存グラフが残差ストリーム上で線形にデコード可能であることを初めて実証した研究である。AUROC 0.869（直接辺）・0.986（推移的辺）を達成し、ランダムラベル制御・反事実的対照・activation patchingで多角的に検証されている。対話的フィードバックが依存構造の内部表現を駆動するという知見は、逐次的ツール実行パターンの合理性を裏付ける。著者らは限界として、Qwen3-32Bへの検証集中と、表現変化が行動に直結しない点を挙げている。
