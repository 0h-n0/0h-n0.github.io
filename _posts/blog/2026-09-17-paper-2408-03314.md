## 論文概要

テスト時（推論時）にLLMが利用できる計算リソースをどのように配分すれば最大の性能向上が得られるかを体系的に分析した研究である。著者らは、問題の難易度に応じて計算リソースを適応的に配分する「compute-optimal」スケーリング戦略を提案し、MATHベンチマークにおいて一律配分と比較して4倍の計算効率改善を達成したと報告している。さらに、小規模モデルに戦略的なテスト時計算を投入することで、14倍のパラメータを持つ大規模モデルに匹敵する性能を達成可能であることを示した。この知見は、モデルの事前学習コストとデプロイ時コストのトレードオフに関する新たな設計指針を提供する。

## 背景と動機

LLMの性能向上手段は大きく2つに分類される。第一は事前学習の規模拡大（パラメータ数、学習データ量、学習計算量）であり、Chinchilla則に代表されるスケーリング法則が知られている。第二はテスト時（推論時）計算の拡大であり、複数の応答候補を生成して最良のものを選択する手法や、段階的に推論を修正する手法が含まれる。

しかし、テスト時計算の投入方法に関する体系的な分析は十分ではなかった。具体的には以下の問いが未解決であった。

1. **最適な計算配分**: 全問題に均一に計算を割り当てるべきか、問題ごとに適応させるべきか
2. **探索 vs 修正**: 候補を並列に生成して選別する方式と、逐次的に修正を重ねる方式のどちらが優れるか
3. **事前学習との交換**: テスト時計算は事前学習によるパラメータ増大をどの程度代替しうるか

著者らは、これらの問いに定量的に答えることで、推論コストの設計指針を確立することを目指している。

## 主要な貢献

著者らが主張する本論文の貢献は以下の通りである（論文Section 1より）。

- **Compute-Optimalスケーリング戦略**: 問題の難易度を5段階に分類し、難易度ごとに異なる推論手法と計算予算を動的に割り当てることで、一律Best-of-N配分と比較して同等性能を4倍少ない計算で達成

## 技術的詳細

### Compute-Optimal戦略

本論文の中核的な知見は、テスト時計算の一律配分が最適ではないという点である。著者らは以下の手順でcompute-optimal戦略を構築する。

**Step 1: 難易度分類**

ベースモデルの pass@1 正答率に基づき、問題を5つの難易度ビン（bin）に分類する。

$$
\text{difficulty}(q) = \text{bin}\left(\frac{\text{correct}(q, N_{\text{eval}})}{N_{\text{eval}}}\right)
$$

ここで $q$ は問題、$N_{\text{eval}}$ は評価用サンプル数、$\text{correct}(q, N)$ は $N$ 回の生成中の正答数である。Oracle分類では真の正答情報を用い、実用的なModel-Predicted分類ではPRMの検証スコアを代替指標として利用する。

**Step 2: 難易度別最適手法の選定**

難易度ビンごとに、固定計算予算 $C$ の下で最良の性能を達成する手法を選定する。

$$
m^*(d) = \arg\max_{m \in \mathcal{M}} \text{Acc}(m, d, C)
$$

ここで $d$ は難易度ビン、$\mathcal{M}$ は候補手法の集合（Best-of-N, Beam Search, Sequential Revision等）、$\text{Acc}$ は正答率である。

**Step 3: 計算予算の最適配分**

全体の計算予算 $C_{\text{total}}$ を難易度ビン間で配分する最適化問題を解く。

$$
\max_{\{C_d\}} \sum_{d} w_d \cdot \text{Acc}(m^*(d), d, C_d) \quad \text{s.t.} \quad \sum_{d} w_d \cdot C_d = C_{\text{total}}
$$

ここで $w_d$ は難易度ビン $d$ に属する問題の割合である。この最適化により、容易な問題には少ない計算を、中程度の問題に計算を集中させ、最難問には過度な投資を避けるという適応的配分が実現される。

### Process-Based Reward Model（PRM）と探索手法

PRMは、モデルの生成した解答の各中間ステップに対して正答確率を予測する検証器である。

$$
\text{PRM}(s_1, s_2, \ldots, s_k) = \prod_{i=1}^{k} p_{\text{correct}}(s_i \mid s_1, \ldots, s_{i-1})
$$

ここで $s_i$ は $i$ 番目の推論ステップである。訓練にはモンテカルロ・ロールアウトによる推定を用い、人手によるステップ単位アノテーションは不要である。

著者らは3つの探索手法を比較している。

以下に、Best-of-N WeightedとBeam SearchのPRM統合ロジックを示す。

```python
from collections import Counter
from typing import NamedTuple


class Solution(NamedTuple):
    """モデルが生成した1つの解答候補."""

    steps: list[str]
    final_answer: str


def prm_score(steps: list[str], prm_model) -> float:
    """PRMによるステップ単位スコアの積を計算する.

    Args:
        steps: 推論ステップのリスト
        prm_model: 訓練済みProcess-Based Reward Model

    Returns:
        全ステップの正答確率の積
    """
    score = 1.0
    for i, step in enumerate(steps):
        step_prob = prm_model.predict(steps[: i + 1])
        score *= step_prob
    return score


def best_of_n_weighted(
    solutions: list[Solution],
    prm_model,
) -> str:
    """Best-of-N Weighted: PRMスコアで重み付けした多数決.

    論文Section 3.1の手法。各候補の最終回答をPRMスコアで
    重み付けし、最も重みの大きい回答を選択する。

    Args:
        solutions: N個の候補解答
        prm_model: 訓練済みPRM

    Returns:
        最も重みの大きい最終回答
    """
    weighted_votes: dict[str, float] = {}
    for sol in solutions:
        score = prm_score(sol.steps, prm_model)
        answer = sol.final_answer
        weighted_votes[answer] = weighted_votes.get(answer, 0.0) + score
    return max(weighted_votes, key=weighted_votes.get)


def beam_search_with_prm(
    prompt: str,
    llm,
    prm_model,
    beam_width: int = 4,
    max_steps: int = 8,
    expansions_per_beam: int = 4,
) -> str:
    """Beam Search: ステップ単位でPRMスコアが高い経路を探索.

    論文Section 3.1の手法。各ステップで複数の候補を展開し、
    PRMスコアの上位beam_width本を保持して次ステップに進む。

    Args:
        prompt: 問題文
        llm: 言語モデル
        prm_model: 訓練済みPRM
        beam_width: 保持するビーム数
        max_steps: 最大ステップ数
        expansions_per_beam: 各ビームからの展開数

    Returns:
        最高スコア経路の最終回答
    """
    beams: list[tuple[list[str], float]] = [([], 1.0)]

    for _step in range(max_steps):
        candidates: list[tuple[list[str], float]] = []
        for steps, cumulative_score in beams:
            # 各ビームからexpansions_per_beam個の次ステップを生成
            next_steps = llm.generate_next_steps(
                prompt, steps, n=expansions_per_beam
            )
            for next_step in next_steps:
                new_steps = steps + [next_step]
                step_score = prm_model.predict(new_steps)
                candidates.append((new_steps, cumulative_score * step_score))

        # 上位beam_width本を保持
        candidates.sort(key=lambda x: x[1], reverse=True)
        beams = candidates[:beam_width]

        # 全ビームが終了条件を満たしたら停止
        if all(
            _is_terminal(steps) for steps, _ in beams
        ):
            break

    best_steps, _ = max(beams, key=lambda x: x[1])
    return _extract_answer(best_steps)


def _is_terminal(steps: list[str]) -> bool:
    """解答が完了しているか判定する."""
    if not steps:
        return False
    return "\\boxed{" in steps[-1] or "The answer is" in steps[-1]


def _extract_answer(steps: list[str]) -> str:
    """最終ステップから回答を抽出する."""
    return steps[-1] if steps else ""
```

### Sequential Revision（逐次修正）

探索手法の代替として、モデル自身が前回の出力を修正する逐次修正アプローチも検証されている。著者らはこれを以下のように定式化する。

$$
r_t = \text{LLM}(q, r_{t-1}, f_{t-1})
$$

ここで $r_t$ は $t$ 回目の修正結果、$f_{t-1}$ は前回の検証フィードバックである。固定予算 $C$ の下で、並列生成数 $N$ と修正回数 $T$ のトレードオフ（$C = N \times T$）が生じる。

## 実装のポイント

PRMの訓練において、著者らは人手によるステップ単位のラベル付けを回避し、モンテカルロ・ロールアウトによる自動推定を採用している。具体的には、各中間ステップから複数のロールアウトを実行し、最終的な正誤をもってそのステップの正答確率を推定する。この手法により、PRMの訓練コストを大幅に削減しつつ、実用的な精度を達成している。

Beam Searchの実装では、ステップの粒度定義が重要である。論文ではMATHベンチマークの解答を改行区切りでステップ分割しており、この粒度がPRMの予測精度とBeam Searchの探索効率に直接影響する。粒度が粗すぎるとPRMの判別力が低下し、細かすぎると探索空間が爆発するため、タスク特性に応じた調整が必要となる。

| 困難（pass@1 < 0.2） | 微小な改善 | 微小な改善 | いずれも限定的 |

### Compute-Optimal戦略の効果（論文Figure 5, 6より）

| 戦略 | 計算予算256での正答率 | 同等性能の最小予算 |
|------|---------------------|-------------------|
| 一律Best-of-N | ベースライン | 256 |

著者らによれば、compute-optimal戦略は一律Best-of-Nと同等の性能を約4分の1の計算予算で達成する。特に中難易度の問題にBeam Searchの計算を集中させ、容易な問題にはBest-of-Nの少数サンプルで十分であるという知見が、この効率改善の鍵となっている。

### 事前学習 vs テスト時計算のトレードオフ（論文Figure 7より）

小規模モデル（PaLM 2-S*）にcompute-optimal戦略を適用した場合、約14倍のパラメータを持つ大規模モデルのgreedy decodingと同等の性能を達成する。ただし、この優位性は推論トークン予算の比率 $R$ に依存する。

- $R < 1$（テスト時計算が安い場合）: テスト時計算が事前学習を代替しうる
- $R \gg 1$（テスト時計算が高い場合）: 事前学習による大規模モデルが有利
- 最難問に対しては、いずれの条件でも事前学習の優位が保たれる

## 実運用への応用

本論文の知見は、推論時にLLMの計算リソースを動的に制御するシステム設計に直結する。Zenn記事「[拡張思考モデル時代のReAct+CoT再設計](https://zenn.dev/0h_n0/articles/e8b5b05c0cf994)」で議論されているAnthropicの拡張思考（extended thinking）における`budget_tokens`パラメータは、まさにこの論文が提唱するテスト時計算のスケーリングの実装例と位置づけられる。

具体的には、以下の設計指針が導出される。

1. **難易度に応じた動的計算配分**: 容易なクエリには少ない思考トークンを割り当て、複雑な推論が必要なクエリには多くのトークンを投入する。本論文のcompute-optimal戦略はこの配分の理論的根拠を提供する
2. **探索手法の使い分け**: 単純な回答検証にはBest-of-N（多数決）、多段推論にはBeam Search的なステップ単位の検証が有効であるという知見は、エージェントフレームワークにおけるReActループの設計に示唆を与える
3. **コスト-性能のトレードオフ管理**: 小規模モデル＋推論時計算の組み合わせが大規模モデルの直接推論に匹敵する条件が明確化されたことで、デプロイコストの最適化が可能となる
