## 論文概要（Abstract）

拡散ベース大規模言語モデル（Diffusion LLM, 以下dLLM）は非自己回帰型のテキスト生成で並列デコードが可能だが、オープンソースのdLLMの実用的な推論速度は自己回帰（AR）モデルに及ばない。原因は(1) 双方向attentionによるKVキャッシュの欠如と(2) 並列デコード時のトークン依存関係破壊による品質劣化である。Fast-dLLMはこの2つの問題に対し、ブロック近似KVキャッシュと信頼度閾値デコードという追加訓練不要な手法を提案し、LLaDAおよびDreamモデルで最大27.6倍のスループット改善を達成したと報告されている。

本記事は <https://arxiv.org/abs/2505.22618> の解説記事です。

## 背景と動機（Background & Motivation）

自己回帰（AR）モデルはトークンを逐次生成するため、KVキャッシュによって過去の計算を再利用でき推論が効率的である。一方、dLLMは全マスクトークンを同時に更新（denoise）する非自己回帰型のアーキテクチャであり、原理的にはARモデルより高い並列性を持つ。しかし実際の推論速度はARモデルを下回ることが多い。

この性能ギャップには2つの技術的要因がある。第一に、dLLMは双方向attention（bidirectional attention）を使用するため、ARモデルのようなcausal maskに基づくKVキャッシュをそのまま適用できない。denoiseステップごとにマスクトークンの表現が変化するため、全位置のKVを毎ステップ再計算する必要がある。第二に、dLLMの並列デコードは条件付き独立性の仮定に依存しており、実際にはトークン間に存在する依存関係を無視することで生成品質が劣化する。

著者らはこれらの問題を追加訓練なし（training-free）で解決するフレームワークとしてFast-dLLMを提案している。

## 主要な貢献（Key Contributions）

- **ブロック近似KVキャッシュ**: dLLMの双方向attention用にKVキャッシュの近似的再利用を実現する手法。隣接するdenoiseステップ間でKV活性化のコサイン類似度が高いという実験的観察に基づき、ブロック単位でキャッシュを再利用する
- **信頼度閾値デコード（Confidence-Threshold Decoding）**: 条件付き独立性の仮定によるトークン依存関係の破壊を軽減する。信頼度が閾値を超えたトークンのみを先行確定し、残りのマスクトークンに計算資源を集中させる
- **理論的正当化**: 個々のトークン信頼度が十分高い場合、周辺分布の積による貪欲並列デコードが真の同時分布による逐次デコードと一致することを定理として証明

## 技術的詳細（Technical Details）

### ブロック近似KVキャッシュ

ARモデルではcausal maskにより、過去トークンのKey・Value表現が後続トークンの生成に影響を受けないため、KVキャッシュが厳密に成立する。dLLMでは双方向attentionを用いるため、マスクトークンの更新に伴い全位置のKV表現が変化し得る。

著者らは実験的に、隣接するdenoiseステップ $i$ と $j$ のKV活性化間のコサイン類似度が $i \approx j$ の近傍で1に近いことを確認している（論文Figure 3）。この観察に基づき、生成対象の系列をブロックサイズ $B$ のブロック $K$ 個に分割し、ブロック内の $T$ denoiseステップ間ではKVキャッシュを近似的に再利用する戦略を提案している。

具体的には、DualCacheと呼ばれる手法でプレフィックス（確定済み）トークンとサフィックス（未確定マスク）トークンの両方のKVをキャッシュする。

$$
\mathbf{K}_{\text{cache}} = [\mathbf{K}_{\text{prefix}}; \mathbf{K}_{\text{suffix}}], \quad
\mathbf{V}_{\text{cache}} = [\mathbf{V}_{\text{prefix}}; \mathbf{V}_{\text{suffix}}]
$$

ここで、
- $\mathbf{K}_{\text{prefix}}, \mathbf{V}_{\text{prefix}}$: 既に確定したトークン（現在のブロックより前）のKey・Value
- $\mathbf{K}_{\text{suffix}}, \mathbf{V}_{\text{suffix}}$: まだマスクされているトークン（現在のブロックより後）のKey・Value

あるブロックの生成を開始する前に、他のブロックのKVを計算・保存する。ブロック内の $T$ ステップではこのキャッシュを再利用し、ブロック完了後に全ブロックのKVを再計算して更新する。この方式により、ブロック内のステップではattention計算の対象がブロック内トークンのみに縮小され、計算量が大幅に削減される。

### 信頼度閾値デコード

dLLMの並列デコードでは、マスクされた全トークン位置の予測を同時に行う。しかし、各トークンの予測は他のマスクトークンの値に依存しており、条件付き独立性の仮定はこの依存関係を無視する。

著者らはこの問題に対し、各トークン位置 $j$ の信頼度スコア $c_j$ を最大softmax確率として定義する。

$$
c_j = \max_{v \in \mathcal{V}} p_\theta(X_j = v \mid \mathbf{x}_{\text{obs}})
$$

ここで、
- $c_j$: 位置 $j$ の信頼度スコア
- $\mathcal{V}$: 語彙集合
- $p_\theta(X_j = v \mid \mathbf{x}_{\text{obs}})$: モデル $\theta$ が観測済みトークン $\mathbf{x}_{\text{obs}}$ を条件として位置 $j$ にトークン $v$ を予測する確率

**閾値ベース戦略**: 信頼度 $c_j$ が閾値 $\tau$ を超えるトークンのみをアンマスクし、残りはマスクのまま次のステップに回す。全トークンが $\tau$ を下回る場合は、最大信頼度のトークン1つのみをアンマスクする安全条項が設けられている。

**理論的保証（Theorem 1）**: 各トークンの信頼度が $p_j(X_j = x_j \mid E) > 1 - \varepsilon$ を満たし、$\varepsilon \leq 1/(n+1)$ であるとき、周辺分布の積による貪欲並列デコードが真の同時分布による貪欲逐次デコードと一致する。ここで $n$ は同時にデコードするトークン数、$E$ は観測されたイベントである。

**Factor（因子）ベース戦略**: 信頼度を降順にソートし、上位 $n$ トークンが以下の条件を満たす最大の $n$ を求める。

$$
(n+1)(1 - c^{(n)}) < f
$$

ここで $c^{(n)}$ は信頼度の降順ソートにおける $n$ 番目の値、$f$ は固定のハイパーパラメータである。この条件はTheorem 1の十分条件を実用的に緩和したものであり、信頼度が高いトークンほど多くを並列にデコードし、不確実な状況では保守的にデコード数を減らす適応的な振る舞いを実現する。

### ARモデルとの性能差を埋める仕組み

dLLMがARモデルに推論速度で劣る主因は、denoiseステップごとの全系列attention再計算である。Fast-dLLMはブロック近似KVキャッシュでこの計算量を削減し、信頼度閾値デコードで必要なdenoiseステップ数（NFE: Number of Function Evaluations）自体を削減する。両手法の組み合わせにより、バッチサイズ1の条件でARモデル（LLaMA）に匹敵するスループットを達成したと報告されている（論文Figure 9）。

## アルゴリズム

以下は論文Algorithm 1に基づくブロック単位信頼度デコードの擬似コードである。

```python
import torch
import torch.nn.functional as F
from dataclasses import dataclass


@dataclass
class FastDLLMConfig:
    """Fast-dLLM generation configuration.

    Args:
        num_blocks: Number of blocks to divide the answer into (K).
        block_size: Number of tokens per block (B).
        steps_per_block: Denoising steps per block (T).
        confidence_threshold: Threshold for unmasking tokens (tau).
        use_dual_cache: Whether to cache both prefix and suffix KVs.
    """
    num_blocks: int = 8
    block_size: int = 32
    steps_per_block: int = 12
    confidence_threshold: float = 0.9
    use_dual_cache: bool = True


def fast_dllm_generate(
    model: torch.nn.Module,
    prompt_ids: torch.Tensor,
    config: FastDLLMConfig,
) -> torch.Tensor:
    """Block-wise confidence-aware parallel decoding for diffusion LLMs.

    Args:
        model: Diffusion LLM (e.g., LLaDA, Dream).
        prompt_ids: Prompt token IDs, shape (1, prompt_len).
        config: Generation configuration.

    Returns:
        Generated token IDs, shape (1, prompt_len + K * B).
    """
    K, B, T = config.num_blocks, config.block_size, config.steps_per_block
    tau = config.confidence_threshold
    device = prompt_ids.device
    answer_len = K * B

    # Initialize answer tokens as [MASK]
    mask_token_id = model.mask_token_id
    answer_ids = torch.full((1, answer_len), mask_token_id, device=device)
    full_seq = torch.cat([prompt_ids, answer_ids], dim=1)
    prompt_len = prompt_ids.shape[1]

    for k in range(K):
        block_start = prompt_len + k * B
        block_end = block_start + B

        # Compute and cache KV for non-block positions
        if config.use_dual_cache:
            kv_cache = compute_dual_cache(model, full_seq, block_start, block_end)
        else:
            kv_cache = compute_prefix_cache(model, full_seq, block_start)

        for t in range(T):
            # Forward pass on block with cached KV
            logits = model.forward_with_cache(
                full_seq, kv_cache, block_start, block_end
            )  # (1, B, vocab_size)

            # Compute confidence scores
            probs = F.softmax(logits, dim=-1)  # (1, B, vocab_size)
            confidence, predicted = probs.max(dim=-1)  # (1, B)

            # Identify masked positions in the block
            block_tokens = full_seq[0, block_start:block_end]
            masked = block_tokens == mask_token_id  # (B,)

            if not masked.any():
                break  # All tokens already unmasked

            # Apply confidence threshold
            to_unmask = masked & (confidence[0] >= tau)

            # Safety: if nothing exceeds threshold, unmask highest confidence
            if not to_unmask.any():
                masked_confidence = confidence[0].clone()
                masked_confidence[~masked] = -1.0
                best_idx = masked_confidence.argmax()
                to_unmask[best_idx] = True

            # Unmask selected tokens
            full_seq[0, block_start:block_end] = torch.where(
                to_unmask, predicted[0], block_tokens
            )

        # Recompute KV cache after block completion
        kv_cache = None  # Release cache, recompute on next block

    return full_seq[:, prompt_len:]


def compute_dual_cache(
    model: torch.nn.Module,
    full_seq: torch.Tensor,
    block_start: int,
    block_end: int,
) -> dict:
    """Compute KV cache for prefix and suffix (non-block) tokens.

    Args:
        model: Diffusion LLM.
        full_seq: Full sequence including prompt and answer.
        block_start: Start index of the current block.
        block_end: End index of the current block.

    Returns:
        Dictionary containing cached Key and Value tensors.
    """
    prefix = full_seq[:, :block_start]
    suffix = full_seq[:, block_end:]
    non_block = torch.cat([prefix, suffix], dim=1)
    with torch.no_grad():
        kv = model.compute_kv(non_block)
    return kv
```

上記はアルゴリズムの構造を示す擬似コードであり、`model.forward_with_cache` や `model.compute_kv` はdLLMの内部実装に依存する。実際のLLaDAやDreamでの実装では、attentionレイヤーごとにキャッシュの挿入・再利用ロジックを組み込む必要がある。

## 実装のポイント（Implementation）

**ブロックサイズの選択**: 著者らの実験（論文Table 4）ではブロックサイズ32が最適とされている。ブロックサイズが小さすぎるとキャッシュ再計算の頻度が上がり効率が低下し、大きすぎるとキャッシュの近似精度が劣化する。ただしLLaDA-V（マルチモーダル）ではブロックサイズ96未満で精度が8%以上低下すると報告されており、モデルアーキテクチャに応じた調整が必要である。

**信頼度閾値の設定**: デフォルト閾値は $\tau = 0.9$ が推奨されている。閾値を低くするとスループットは向上するがNFEが増大し、高くすると保守的なデコードとなりスループットが低下する（論文Figure 5）。Factor戦略は閾値戦略に比べて40-50%のスループット改善を追加で達成する一方、精度の低下は1-3%程度に抑えられると報告されている（論文Table 11）。

**バッチサイズの制約**: バッチサイズ1ではPrefixCacheによりARモデル（LLaMA）に匹敵するスループットを達成するが、バッチサイズの増加に伴いdLLMは全系列の双方向attention計算がボトルネックとなり、ARモデルとのスループット差が拡大する（論文Section C.5）。大規模バッチ処理が必要なプロダクション環境では、リクエスト分散やバッチサイズの制限を検討する必要がある。

**ハードウェア要件**: 論文の実験はNVIDIA A100 GPUで実施されている。

def handle_request(event: dict) -> dict:
    """Inference handler with X-Ray tracing."""
    with xray_recorder.in_subsegment("fast_dllm_inference") as seg:
        seg.put_annotation("model", "llada-8b")
        seg.put_annotation("block_size", 32)

            "use_dual_cache": True,
        })

    return result

## 実験結果（Results）

著者らはLLaDA-Instruct（8Bパラメータ）およびDream-Base（7B）で複数のベンチマークを評価している。以下に主要な結果を示す。

### LLaDA-Instruct（論文Table 1より）

| ベンチマーク | 設定 | ベースライン精度 | Fast-dLLM精度 | スループット倍率 |
|-------------|------|----------------|--------------|----------------|
| GSM8K | 5-shot, 256 tokens | 79.3% | 78.5% | 8.1x |
| GSM8K | 5-shot, 512 tokens | 79.3% | 77.2% | 11.0x |
| MATH | 4-shot, 256 tokens | - | 33.2% | 5.7x |
| HumanEval | 0-shot, 256 tokens | - | 43.3% | 3.7x |
| MBPP | 3-shot, 512 tokens | - | 13.8% | 9.2x |

### Dream-Base（論文Table 2より）

| ベンチマーク | 設定 | Fast-dLLM精度 | スループット倍率 |
|-------------|------|--------------|----------------|
| GSM8K | 5-shot, 256 tokens | 74.8% | 5.3x |
| MATH | 4-shot, 256 tokens | 37.6% | 5.9x |
| HumanEval | 0-shot, 256 tokens | 54.3% | 2.8x |
| MBPP | 3-shot, 512 tokens | 55.2% | 7.8x |

### 最大スループット（論文Figure 1cより）

8-shot、生成長1024トークン、DualCache使用の条件で最大27.6倍のスループット改善が報告されている。スループット倍率はプレフィックス長と生成長に依存し、生成長が長いほどキャッシュ再利用の恩恵が大きい（256トークンで9.4倍、1024トークンで27.6倍、論文Table 5より）。

### マルチモーダル（LLaDA-V）

LLaDA-Vでの実験ではMathVistaで9.9倍（精度56.6%）、MathVerseで8.5倍（精度28.6%）のスループット改善が報告されている。ただし、ブロックサイズの縮小に対する精度低下がテキストモデルより大きく、ブロックサイズ96未満で8%以上の精度劣化が観察されている。

### 閾値 vs Factor戦略（論文Table 11より）

Factor戦略はGSM8K（256トークン）で11.7倍のスループットを達成し、閾値戦略の8.1倍を上回る。精度低下は1-3%程度に抑えられている。

### バッチサイズスケーリングの制約

バッチサイズ1ではPrefixCacheによりLLaMAに匹敵するスループットを達成するが、バッチサイズ8以降はdLLMの双方向attention計算がボトルネックとなりARモデルとの差が拡大する（論文Section C.5）。

## 実運用への応用（Practical Applications）

Fast-dLLMの手法は、Zenn記事で紹介されているSGLangベースのdLLM推論パイプラインと直接関連する。SGLangのJointThreshold（並列トークンデコードの信頼度閾値制御）はFast-dLLMの信頼度閾値デコードと同様の着想に基づいており、`sgl.JointThreshold(threshold=0.9)` のようなパラメータ設定でFast-dLLMの戦略をサービングフレームワーク上で利用できる。

**プロダクション適用時の考慮事項**:

- **バッチサイズ制約**: 高スループットが得られるのは主にバッチサイズ1の条件である。複数リクエストの同時処理が必要な環境では、リクエストを個別のGPUに分散するか、バッチサイズを小さく保つ設計が求められる
- **精度とスループットのトレードオフ**: 信頼度閾値 $\tau$ を下げるとスループットは向上するが品質が劣化する。用途に応じた閾値チューニングが必要であり、ドメイン固有の評価セットでの検証が推奨される
- **モデル依存性**: ブロックサイズの最適値やキャッシュ近似の精度はモデルアーキテクチャに依存する。LLaDA-Vではテキストモデルと異なる設定が必要であることが報告されており、新しいdLLMへの適用時には事前検証が不可欠である

## 関連研究（Related Work）

- **LLaDA** (Nie et al., 2025): マスク拡散に基づく大規模言語モデル。Fast-dLLMの主要な評価対象。LLaDA 1.5では77Bパラメータへのスケールアップが報告されている
- **Dream** (Dream Team, 2025): もう一つの拡散ベースLLM。Fast-dLLMはDreamモデルでも有効性を実証しており、手法のモデル非依存性を示している
- **MDLM** (Sahoo et al., 2024): マスク拡散言語モデルの先行研究。連続拡散モデルと離散マスキングの接続を理論的に整理した
- **Speculative Decoding** (Leviathan et al., 2023): ARモデルの高速化手法。ドラフトモデルによる投機的デコードはFast-dLLMの信頼度閾値デコードと異なるアプローチで並列性を実現する

## まとめと今後の展望

Fast-dLLMは、追加訓練なしでdLLMの推論を高速化する2つの手法を提案した。ブロック近似KVキャッシュはdLLM固有の双方向attention問題に対する実用的な近似解を提供し、信頼度閾値デコードはトークン依存関係の破壊を軽減しつつ並列性を最大化する。LLaDAおよびDreamで最大27.6倍のスループット改善が報告されており、dLLMの実用化に向けた重要な一歩である。

今後の研究方向としては、バッチサイズスケーリングの改善、マルチモーダルモデルへのブロックサイズ最適化、およびSpeculative Decodingとの組み合わせによるさらなる高速化が考えられる。
