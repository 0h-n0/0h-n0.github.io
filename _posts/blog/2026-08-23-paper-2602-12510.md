## 論文概要

Yeroyan (2026) は、ColPali系マルチベクトル視覚検索のスケーラビリティ問題に対し、training-freeな空間プーリングとマルチステージ検索を組み合わせたオープンソースツールキットVisual RAG Toolkitを提案している。モデル固有のプーリングによりページあたりのベクトル数を約1,024から約32に圧縮し、ViDoRe v2（3,006ページ、union scope）でNDCG・Recall@5/10を$\pm 0.01$以内に維持しつつQPSを約4倍に改善したと報告されている（論文Table 2）。SIGIR 2026 Demonstrations Track投稿。

この記事は [Zenn記事: ColQwen2×vLLMで図表込み社内マニュアル検索を構築する](https://zenn.dev/0h_n0/articles/6e33a242d347f9) の深掘りです。Zenn記事の検索基盤を数万ページ規模に拡張する際に不可欠なスケーラビリティ手法を本論文が提示している。

## 背景と動機

ColPaliファミリー（ColBERTの遅延交互作用を視覚領域に適用したモデル群）は、ページ画像から直接パッチ埋め込みを生成しMaxSim集約で文書関連度を計算することでOCRをバイパスするが、深刻なスケーラビリティ問題がある。著者は検索コストを以下の式で定式化している（論文Section 1）。

$$
\text{Cost}_{\text{search}} = Q \times D \times N \times d \quad \text{(multiply-adds)}
$$

ここで$Q$はクエリトークン数（$\approx 10$）、$D$はページあたりベクトル数（ColPali: $1{,}024$、ColQwen2.5: $700\text{-}750$）、$N$は総ページ数、$d$は埋め込み次元（$128$）である。ColPaliで$N = 10{,}000$ページの場合、1クエリあたり$1.31 \times 10^{10}$回の乗加算が必要となる。HNSWインデキシング構築は$O(D^2 \cdot d)$で数兆回の浮動小数点演算に達する。

既存手法（量子化、PLAIDのセントロイドプルーニング等）は「比較あたりのコスト」を削減するが「比較回数」は削減しない。Visual RAG Toolkitは「ページあたりの格納ベクトル数」を削減する直交アプローチを採る。

## 主要な貢献

- **Training-free, model-aware空間プーリング**: Matryoshka Representation Learning [Kusupati et al., 2022] に着想を得て、追加学習・アダプタ・蒸留なしでパッチ埋め込みを圧縮する。ColSmol-500M向けのタイルレベル平均、ColPali向けの行方向平均+Conv1Dスライディングウィンドウ、ColQwen2.5向けのガウシアン/三角形重み付き平滑化の3戦略を提供
- **Qdrant名前付きベクトルによるマルチステージ検索**: コンパクトなプール表現で高速候補生成（Stage 1）し、完全なマルチベクトル埋め込みでMaxSim rerankingする（Stage 2）2段構成を、Qdrantの`prefetch+query` APIで単一ラウンドトリップにて実行
- **ロバスト前処理・再現可能な評価基盤**: PDF→画像変換、空白マージン除去、トークンハイジーン（非視覚トークンの除外）、2段・3段カスケードのベンチマークスクリプトを含むエンドツーエンドのオープンソースツールキット

## 技術的詳細

### 前処理: トークンハイジーンと空白マージン除去

VLMは視覚パッチ以外にCLS/BOS/EOSなどの特殊トークン、プロンプトトークン、パディングトークンを出力する。標準MaxSimはこれらを等価に扱うため、非視覚トークンが擬似的な高類似度アトラクタとしてスコアを歪める。著者はインデキシング時に非視覚トークンを除去し、ColPaliで1,030→1,024、ColQwen2.5で720-768（平均743）の視覚トークンのみを保持する（論文Section 2.1）。この処理だけで公式ViDoRe v2スコアを上回る場合があると報告されている。

さらに、行/列の標準偏差に基づく閾値で余白・ページ番号を除去する。動的解像度モデルではクロップにより生成パッチ数が直接削減される。

### スライディングウィンドウプーリング

著者の核心的な知見は、パッチ埋め込みの空間構造を利用して、追加学習なしでコンパクトな要約表現を生成できるという点である。モデルのバックボーンアーキテクチャに応じて異なる戦略を開発している。

#### ColSmol-500M: タイルレベル平均プーリング

ColSmol-500Mのプロセッサは各ページを$512 \times 512$ピクセルにリサイズし、$n_{\text{rows}} \times n_{\text{cols}}$のタイルグリッドに分割する（各タイルは$P = 64$パッチトークンを生成）。さらに元画像全体の縮小版として1つのグローバルタイルが追加される。タイル数は$n_{\text{tiles}} = n_{\text{rows}} \cdot n_{\text{cols}} + 1$で、典型的には$12 + 1 = 13$タイル、計約832の視覚トークンとなる。

各タイルグループ内で平均プーリングを行い、タイルあたり1ベクトルを生成する。

$$
\mathbf{t}_i = \frac{1}{P} \sum_{p=1}^{P} \mathbf{x}_{(i,p)} \in \mathbb{R}^d, \quad i = 1, \ldots, n_{\text{tiles}}
$$

ここで、
- $\mathbf{x}_{(i,p)}$: タイル$i$の$p$番目のパッチ埋め込み（$d = 128$次元）
- $P = 64$: タイルあたりのパッチ数

結果として約832ベクトルが約13ベクトルに圧縮され、約64倍の圧縮率となる。

#### ColPali (v1.3): 行方向平均+Conv1Dスライディングウィンドウ

ColPaliは固定$32 \times 32$のパッチグリッド（1,024視覚トークン、$d = 128$）を使用する。まず、トークンを2Dグリッドに再構成し、列方向に平均プーリングして$H = 32$本の行ベクトルを生成する。

$$
\mathbf{r}_h = \frac{1}{W} \sum_{w=1}^{W} \text{grid}[h, w] \in \mathbb{R}^d, \quad h = 1, \ldots, H
$$

ここで、
- $H = W = 32$: グリッドの行数・列数
- $\text{grid}[h, w]$: 位置$(h, w)$のパッチ埋め込み

結果: $1{,}024 \to 32$行ベクトル（32倍圧縮）。

さらに、行ベクトルの上に窓サイズ$k = 3$、半径$r = 1$の均一スライディングウィンドウを適用し、行間の文脈を追加する。$N$本の入力行ベクトルから$N + 2$本の出力ベクトルを生成する。

$$
\mathbf{y}_i = \frac{1}{|W_i|} \sum_{j \in W_i} \mathbf{r}_j, \quad W_i = \{j : |j - (i - r)| \leq r, \; 0 \leq j < N\}
$$

ここで、
- $W_i$: 位置$i$の窓内のインデックス集合
- 境界外（$[0, N)$外）のインデックスはスキップされ、重みは再正規化される

著者はColPaliの場合、バックボーンに学習済みの局所的混合（learned local mixing）が存在しないため、均一平均でも十分に機能すると述べている（論文Section 2.3.2）。

#### ColQwen2.5 (v0.2): ガウシアン/三角形重み付き平滑化

ColQwen2.5はQwen2-VLベースで、内部のPatchMergerが$2 \times 2$ブロックを学習済みのLayerNorm→連結→MLPで融合する。各出力トークンが既に$2 \times 2$近傍をエンコードしているため、ColPaliのConv1Dアプローチを適用すると二重平滑化で識別的特徴が消失し品質が劣化する（論文Section 2.3.3）。

そこで著者は同長平滑化（$N \to N$）で非均一な重み付けを行う方式を設計した。窓サイズ$k = 3$（$r = 1$）で以下を適用する。

$$
\mathbf{y}_i = \frac{1}{Z_i} \sum_{j=i-r}^{i+r} w_{|j-i|} \; \mathbf{r}_j, \quad Z_i = \sum_{\substack{j=i-r \\ 0 \leq j < N}}^{i+r} w_{|j-i|}
$$

- **ガウシアン**: $w_\delta = \exp(-\delta^2 / 2\sigma^2)$, $\sigma = \max(0.5, r/2)$; 重み $\approx [0.61, 1.0, 0.61]$
- **三角形**: $w_\delta = (r + 1) - \delta$; 重み $= [1, 2, 1]$

ガウシアン（$\sigma \approx 0.5$）が最適であり、急速な減衰が中心トークンのアイデンティティを保持する。動的解像度に対応するため、列方向平均後に適応的ダウンサンプルで最大$T = 32$ベクトルに等間隔ビニングする。

以下に3モデルのプーリング戦略を比較する。

| モデル | 入力ベクトル数 | プーリング手法 | 出力ベクトル数 | 圧縮率 |
|--------|-------------|--------------|-------------|--------|
| ColSmol-500M | ~832 | タイルレベル平均（P=64） | ~13 | 64x |
| ColPali v1.3 | 1,024 | 行方向平均 + Conv1D（k=3, 均一） | ~34 | 32x |
| ColQwen2.5 v0.2 | 700-750 | 列方向平均 + ガウシアン平滑化（k=3） | ~32 | ~23x |

### マルチステージ検索

各ページは`initial`（完全パッチ埋め込み、~700-1,024ベクトル）、`mean_pooling`（~13-32ベクトル）、`experimental_pooling`（平滑化済み、~13-34ベクトル）、`global_pooling`（単一ベクトル）の名前付きベクトルとしてQdrantに格納される。

**2-stage retrieval**: Stage 1でプール表現上のMaxSimにより上位$K = 256$候補をprefetchし、Stage 2で`initial`上の正確なMaxSimでrerankingする。Qdrantの`prefetch+query` APIで単一ラウンドトリップにて実行される。**3-stage cascade**は`global_pooling`による超高速prefetchを追加する構成で、ColSmol-500Mのように品質低下が大きいモデルで一部のRecallを回復する。

ツールキットはPDF→画像変換→マージン除去→埋め込み生成→トークンハイジーン→空間プーリング→Qdrantインデキシング→マルチステージ検索のエンドツーエンドパイプラインを提供する。

## 実装のポイント

Visual RAG Toolkitは`pip install visual-rag-toolkit`でインストール可能なPythonパッケージとして公開されている。以下に実装上の主要な考慮事項を整理する。

**モデル選択**: 3モデルとも500M-3Bパラメータで消費者向けGPUで動作する。3Bクラス（ColPali, ColQwen2.5）は品質劣化ほぼゼロ、ColSmol-500Mは軽量だが品質低下が大きい。

**ベクトル精度**: FP16格納（リーダーボードのFP32より低精度）。トークンハイジーンとクロッピングにより低精度でも公式スコアを上回る場合がある（論文Section 4）。

**プーリング戦略**: ColPaliにはConv1D、ColQwen2.5にはガウシアン平滑化。ColQwen2.5にConv1Dを誤適用するとPatchMergerと干渉し品質劣化するため、モデル別選択が重要である。

**prefetch_K**: デフォルト$K = 256$。$k \leq 10$では2-stageの品質劣化はほぼゼロである。

以下にVisual RAG Toolkitを用いた2-stage検索の実装例を示す。

```python
from qdrant_client import QdrantClient
from visual_rag import VisualEmbedder
from visual_rag.indexing import ProcessingPipeline, QdrantIndexer
from visual_rag.retrieval import TwoStageRetriever


def search_documents(
    query: str,
    collection_name: str,
    qdrant_url: str,
    model_name: str = "vidore/colpali-v1.3",
    top_k: int = 10,
    prefetch_k: int = 256,
) -> list[dict]:
    """2-stage検索: pooled vectorsでprefetch後、full embeddingsでrerank

    Args:
        query: 検索クエリ文字列
        collection_name: Qdrantコレクション名
        qdrant_url: QdrantサーバーURL
        model_name: ColPali/ColQwen2.5/ColSmolのモデル名
        top_k: 最終返却件数
        prefetch_k: Stage 1の候補数（デフォルト256）

    Returns:
        検索結果のリスト（スコア降順）
    """
    client = QdrantClient(url=qdrant_url)
    embedder = VisualEmbedder(model_name=model_name)
    retriever = TwoStageRetriever(client=client, collection_name=collection_name)
    return retriever.search_server_side(
        query_embedding=embedder.embed_query(query),
        top_k=top_k,
        prefetch_k=prefetch_k,
        stage1_mode="tokens_vs_experimental_pooling",
    )
```

## Production Deployment Guide

### AWS実装パターン（コスト最適化重視）

Visual RAG Toolkitの本番運用では、PDFインジェスト（バッチ）、ベクトルインデキシング（Qdrant）、マルチステージ検索（リアルタイム）の3ワークロードを考慮する。GPUは埋め込み生成にのみ必要であり、検索はQdrant側で完結する。

| 構成 | トラフィック | 主要サービス | 月額概算 |
|------|-------------|-------------|---------|
| Small | ~100 req/日 | Lambda + Qdrant Cloud Free + S3 | $30-100 |
| Medium | ~1,000 req/日 | ECS Fargate (GPU) + Qdrant Cloud + S3 | $400-1,000 |
| Large | 10,000+ req/日 | EKS + Karpenter (Spot GPU) + Qdrant Dedicated | $3,000-8,000 |

Small構成はLambda + Qdrant Cloud Free Tier（1GBまで）+ S3で構成する。ColPali系の視覚埋め込みにはGPU推論が必要なため、Medium以上ではFargate/EKSでGPUエンドポイントを用意する。Large構成はEKS + Karpenter（g5.xlarge Spot優先、最大90%削減）+ Qdrant Dedicated Cluster + ElastiCache（クエリ埋め込みキャッシュ）で構成する。

## 実験結果

### ViDoRe v2ベンチマーク

著者はViDoRe v2（ページレベルの視覚ドキュメント検索ベンチマーク）の3つのドメイン（ESG Reports: 1,538ページ227クエリ、Biomedical Lectures: 1,016ページ639クエリ、Economics Reports: 452ページ231クエリ、計3,006ページ）で評価している。

評価は2つのスコープで実施されている。(i) **Per-dataset**: 各データセット内のみで検索（公式リーダーボードと同条件）、(ii) **Union (distractor)**: 全3,006ページを単一コレクションに統合し、各クエリがクロスドメインのディストラクタの中から関連ページを発見する必要がある設定である。

以下にunionスコープ（3,006ページ、トークンハイジーン適用）の主要結果を示す（論文Table 2）。ESGドメインの代表値を抜粋する。

| モデル | 構成 | N@5 | N@10 | R@5 | R@10 | QPS |
|--------|------|-----|------|-----|------|-----|
| ColPali v1.3 | 1-stage base | .551 | .573 | .570 | .661 | 0.28 |
| ColPali v1.3 | 2-stage Conv1d | .559 | .576 | .576 | .662 | 1.27 |
| ColQwen2.5 | 1-stage base | .509 | .564 | .538 | .704 | 0.31 |
| ColQwen2.5 | 2-stage Gauss. | .513 | .560 | .549 | .690 | 1.15 |
| ColSmol-500M | 1-stage base | .404 | .457 | .460 | .620 | 0.50 |
| ColSmol-500M | 2-stage tiles | .369 | .401 | .405 | .503 | 1.32 |

3Bモデル（ColPali, ColQwen2.5）では、2-stage検索がN@5, N@10, R@5, R@10を1-stage baselineから$\pm 0.01$以内に維持しつつ、**QPSを約3.8-4.5倍に改善**している。品質劣化はR@100（$-0.02$から$-0.09$）でのみ顕在化し、prefetchウィンドウ$K = 256$の上限に起因する。$k \leq 10$では最適化効果が大きいと著者は報告している。

**ColSmol-500M**: 500Mパラメータではプーリングによる品質低下が大きい（R@100最大$-0.30$）。3-stage cascadeで一部回復するが3Bモデルほどの効果はない。

**スループット**: per-dataset（452-1,538ページ）で約2倍、union（3,006ページ）で約4倍QPSの改善。1-stageコストが$N$に線形増加する一方、2-stageのrerankingは$K = 256$に固定されるため、コーパス増大に伴い倍率も増大する。

**コスト削減**: プーリングで$D = 1{,}024 \to D' = 32$とすると、検索コストは$32$倍削減される。$10 \times 32 \times 10{,}000 \times 128 = 4.10 \times 10^8$（vs. $1.31 \times 10^{10}$）。次元$d$が相殺されるため削減率は圧縮率$D/D'$のみに依存する（論文Section 1）。

## 実運用への応用

### Qdrantブログのrow-wise poolingとの比較

Qdrant公式ブログでもColPaliのスケーラビリティ問題に対するrow-wise poolingの手法が紹介されている。両者の比較を以下にまとめる。

| 観点 | Qdrantブログ | Visual RAG Toolkit |
|------|-------------|-------------------|
| プーリング手法 | Row-wise mean pooling | Row-wise mean + Conv1D sliding window |
| ベクトル削減 | 1,030 → 38（27倍） | 1,024 → ~32（32倍） |
| 対応モデル | ColPali | ColPali + ColQwen2.5 + ColSmol-500M |
| 追加学習 | 不要 | 不要 |
| モデル固有戦略 | 単一 | モデル別（Conv1D / Gaussian / Tile-level） |
| マルチステージ | 未実装 | 2-stage / 3-stage cascade |
| 前処理 | なし | トークンハイジーン + マージン除去 |

両者ともtraining-freeで追加学習不要という共通点がある。Visual RAG Toolkitの差別化はモデル別のプーリング戦略とマルチステージ検索の統合にあり、特にColQwen2.5でConv1Dが失敗しガウシアン平滑化が必要であるという知見は実運用で重要である。

### 社内マニュアル検索への適用

Zenn記事のColQwen2×vLLM構成にVisual RAG Toolkitを適用する場合、(1) トークンハイジーンで非視覚トークンを除去、(2) ガウシアンプーリング（$\sigma \approx 0.5$, $k = 3$）で700-750ベクトルを約32に圧縮、(3) Qdrantの名前付きベクトルで2-stage retrievalを導入、(4) 空白マージン除去で追加のベクトル数削減、という手順が想定される。数万ページ規模では2-stageのprefetchウィンドウ固定によりスケーリングに伴うQPS改善倍率の増大が見込まれる。

**制約事項**: (1) プーリング戦略がモデル固有で新アーキテクチャには個別対応が必要、(2) ColQwen2.5にConv1Dを誤適用すると品質劣化、(3) 500Mクラスでは品質低下が顕著、(4) R@100での劣化があり大量候補が必要なユースケースでは注意が必要。

## 関連研究

- **ColPali** [Faysse et al., 2024]: PaliGemma-3BベースのColBERT視覚拡張。1,024ベクトル生成のスケーラビリティ問題をVisual RAG Toolkitが解決する位置づけである
- **Matryoshka Representation Learning** [Kusupati et al., 2022]: 複数粒度の表現抽出。本手法はこの着想を追加学習なしの静的空間操作で実現
- **PLAID** [Santhanam et al., 2022]: ColBERTのセントロイドプルーニング。「比較あたりのコスト削減」であり本手法の「比較回数削減」とは直交し、組み合わせで乗法的効率向上が期待される

## まとめと今後の展望

Visual RAG Toolkitは、ColPali系マルチベクトル視覚検索モデルのスケーラビリティ問題に対し、training-freeなモデル固有空間プーリング（ページあたり約1,024ベクトルを約32に圧縮）とマルチステージ検索（プール表現でprefetch、完全表現でreranking）の組み合わせにより、ViDoRe v2で$k \leq 10$の品質をほぼ維持しつつQPSを約4倍に改善するフレームワークである。

著者は今後の方向として、(1) プール表現のみの1-stage検索で実用的な品質を達成し完全パッチベクトルの格納を不要にすること、(2) 軽量アダプタ等の学習済みプーリングによる小型モデルの品質ギャップ解消、(3) 量子化やHNSWプルーニング等の直交手法との組み合わせによる乗法的効率向上の3点を挙げている。コーパスサイズの増大に伴いスピードアップ倍率も増大する特性から、大規模実運用環境での適用可能性は高い。
